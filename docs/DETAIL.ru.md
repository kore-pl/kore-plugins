# kore-plugins

Этот репозиторий публикует только `index/plugins.json` (и его подпись ed25519 `plugins.json.sig`), `index/versions.lock.json`, `presets/*.json` и статическую страницу `market/` со скриптами проверки. Индекс отвечает лишь «какие плагины, какая версия, размер, описание»; он не доказывает надёжность пакета: kore пересчитывает sha256 локально и сравнивает. Корень доверия — встроенный в kore открытый ключ и локальные вычисления. Без проверки, аккаунтов, работает офлайн (G-10).

## Что делает проект

- **Канал обнаружения, а не источник доверия**: `sha256` / `download_url` индекса проверяются только перед установкой; корень доверия — встроенный в kore открытый ключ и локальный пересчёт.
- **Цепочка подписей**: `plugins.json.sig` — 64-байтовая ed25519-подпись, переподписывается мейнтейнером на авторитетном источнике; CI проверяет послойно — PR только схема, push main/tag полностью; отсутствие или ошибка подписи = FAIL. Приватный ключ никогда не попадает в репозиторий или секреты CI.
- **Реестр версий**: `versions.lock.json` только дополняется; один sha на `id@version`; изменение пакета требует bumps версии.
- **Восемь пресетов**: `minimal` / `dev` / `web-lite` / `web-pro` / `db-only` / `gateway` / `security` / `full`; `out_of_box=true` не должен включать basic-плагины (G-20).
- **Статический маркет**: `market/index.html` открывается офлайн, без фреймворка, CDN и http(s)-ссылок; `market/plugins.js` встраивается при сборке через `build-market.sh`.
- **Ворота проверки**: `make check` = `validate-index.sh` + `validate-presets.sh` (по умолчанию полная проверка); `KORE_INDEX_SKIP_SIG=1` только для схемы в PR.

## Быстрый старт

```bash
KORE_INDEX_SKIP_SIG=1 make check   # PR: только схема / реестр / ссылки на пресеты
bash scripts/validate-index.sh     # полная проверка индекса (вкл. ed25519)
bash scripts/validate-presets.sh   # проверка пресетов
bash scripts/build-market.sh       # пересобрать market/plugins.js
```

После изменения `plugins.json` мейнтейнер должен переподписать его на авторитетном источнике приватным ключом релизной машины (`KORE_INDEX_KEY=<seed> bash scripts/sign-index.sh`) и запушить содержимое и `.sig` в одном коммите; приватный ключ никогда не попадает в репозиторий или CI.

## Безопасность и границы

О фальсификации индекса, цепочке подписей или цепочке поставок сообщайте через [SECURITY.md](../SECURITY.md) (подтверждение 72 ч / согласованное раскрытие 90 дней); не создавайте публичные issue. **Приватный ключ хранится у мейнтейнера, никогда в репозитории или секретах CI; CI только проверяет, не подписывает.** Смена открытого ключа должна выходить вместе с ядром kore и сохранять один цикл совместимости при ротации.

## Частые вопросы

**В: Нужен ли аккаунт?**
Нет. Нет аккаунтов, онлайн-проверок и скрытой телеметрии; конфигурация хранится в открытом тексте, который можно читать и менять.

**В: Где находятся плагины?**
Каждый плагин живёт в собственном репозитории `kore-plugin-<id>`. Здесь только ядро и публичный SDK.

**В: С какого документа начать?**
Начните с `QUICKSTART.md` (от сборки до первого входа), затем используйте указатель «что я хочу сделать» в `docs/README.md`.
